# rdf — Removing Duplicate Files

Маленькая консольная утилита: ищет в одной папке файлы, которые уже есть в другой, и переносит дубликаты в корзину. Сравнивает по размеру + хэшу содержимого (`XxHash64`), хэширует параллельно, ничего не удаляет — только перемещает, ведёт журнал в JSONL.

## Использование

```
rdf -s <source> -t <target> --trash <trash> [опции]
```

| Опция | Описание |
|---|---|
| `-s, --source <PATH>` | Папка, **из которой** убираются дубликаты |
| `-t, --target <PATH>` | Эталонная папка — с ней сравниваем, **не трогается** |
| `--trash <PATH>` | Куда переносить найденные дубликаты |
| `--dry-run` | Только показать список, ничего не двигать |
| `--threads <N>` | Потоков для хэширования (по умолчанию — число ядер) |
| `--log <PATH>` | Путь к журналу JSONL (по умолчанию — рядом в `--trash`) |

## Примеры

**Посмотреть, что нашлось, ничего не трогая:**
```powershell
rdf -s "D:\Скачанное" -t "D:\Фотоархив" --trash "D:\Trash" --dry-run
```

**Реальный прогон:**
```powershell
rdf -s "D:\Скачанное" -t "D:\Фотоархив" --trash "D:\Trash"
```

**На HDD — ограничить параллелизм:**
```powershell
rdf -s "D:\Downloads" -t "D:\Photos" --trash "D:\Trash" --threads 4
```

**Свой путь к журналу:**
```powershell
rdf -s "D:\A" -t "D:\B" --trash "D:\Trash" --log "D:\Logs\dedup.jsonl"
```

## Что увидите

1. Прогресс сканирования и хэширования (`target`, затем `source`).
2. Таблица первых 10 совпадений и общий объём.
3. В обычном режиме — прогресс перемещения и итог: `Перемещено N из M. Журнал: ...`.

`Ctrl+C` корректно останавливает после текущего файла; журнал сохраняется до точки остановки.

## Журнал

Каждая строка — один перенесённый файл:

```json
{"MovedAtUtc":"2026-05-06T12:34:56Z","From":"D:\\A\\photo.jpg","To":"D:\\Trash\\photo.jpg","MatchedTarget":"D:\\B\\photo.jpg","Size":1048576}
```

По нему можно вручную восстановить любые файлы.

## Ограничения

- Хэш `XxHash64` некриптографический — для бытового удаления дубликатов этого хватает с большим запасом, но математически коллизия возможна.
- Symlinks и junction-папки пропускаются.
- `--source`, `--target`, `--trash` не могут совпадать или быть вложены друг в друга — валидатор не пропустит.
